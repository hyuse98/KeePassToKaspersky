# KeePassToKaspersky

1:1 CSV parser from KeePassXC to Kaspersky Password Manager

## The Problem

Migrating credentials from KeePassXC to Kaspersky Password Manager using CSV files often results in import failures and data loss.
KPM has an extremely strict CSV parser that cannot natively handle raw exports from KeePassXC in certain edge cases.
When attempting a direct import, several issues can prevent entries from being processed successfully:

* **Parser Breakage Due to Commas:** Strong passwords generated by KeePassXC frequently contain commas. Because CSV files use commas as delimiters, Kaspersky Password Manager's importer misinterprets column boundaries and silently drops the entire credential without raising any warning.

* **Failure Caused by Line Breaks:** KeePassXC allows multiline notes. KPM breaks sequential reading whenever it encounters a `\n` (newline) within a text field, corrupting subsequent rows in the file.

* **Missing URLs:** KeePassXC does not require entries to have a URL. In Kaspersky Password Manager, however, the URL is a mandatory field used as a primary key to group credentials. Any entry exported from KeePassXC without a URL will simply be ignored by KPM.

## The Solution

This tool acts as a sanitization middleware: it processes the raw CSV exported from KeePassXC and generates a properly formatted file tailored for Kaspersky, resolving all data normalization issues.

KeePassXC exports CSV data using the following structure:

```
"Group","Title","Username","Password","URL","Notes","TOTP","Icon","Last Modified","Created"
"Root/directory","Gmail","example@gmail.com","2N*'u_;_4S:VK+^z","https://mail.google.com/","","","0","2026-01-01T19:37:00Z","2026-01-01T18:11:40Z"

```

Kaspersky Password Manager requires a completely different structure, as specified in its official documentation: https://support.kaspersky.com.br/kpm-for-windows/26.0/130515

```
url,username,password,name,extra
"https://mail.google.com/","example@gmail.com","2N*'u_;_4S:VK+^z","Gmail",""

```

The 1:1 mapping between fields is defined as follows:

| **Source (KeePass)** | **Target (Kaspersky)** |
| URL | url |
| Username | username |
| Password | password |
| Title | name |
| Notes | extra |

Beyond matching header structures, the algorithm normalizes the data to handle tricky edge cases and prevent import errors:

* **Enforces double quotes (`""`) on all fields**, ensuring KPM correctly parses passwords that include commas.

* **Sanitizes line breaks (`\n` and `\r`)** inside notes, replacing them with safe delimiters.

* **Generates dummy URLs** based on the entry's `Title` for orphaned entries (records without an existing URL).

## How to Use

### Requirements

- Java25+

### Instructions

Place KeePassToKaspersky-v1.jar and the file exported from KeePassXC in the same folder, file must be named like ````keepass_export.csv````.
````
Folder/
├── KeePassToKaspersky-v1.jar
└── keepass_export.csv
````

Open the command prompt or your preferred terminal in the folder and run the JAR using the command line below.
````bash
 java -jar KeePassToKaspersky-V1.jar
````

If everything goes smoothly, the output will be a new file named ````kaspersky_ready.csv````

For your security, it is highly recommended to permanently delete both CSV files after use!!!

### Build

if u want build it u self use the follow commando or use gradle tools on u IDE
